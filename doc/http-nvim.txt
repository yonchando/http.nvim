1. INTRODUCTION                                          *http-nvim-intro*

http-nvim keeps your API requests in Postman collections and lets you
browse, edit and send them without leaving Neovim.

- Browse a collection's folders and requests in a side panel.
- Edit a request as a `.http` file (JetBrains HTTP Client format) and save
  it back to the collection.
- Keep environment variables per collection and use them in requests as
  `{{key}}`.
- Send a request with curl and see the status, response and headers in a
  floating window.
- Set environment variables from the response with a `> {% %}` response
  handler, see |http-nvim-response-handler|.

Each collection lives in its own folder, holding `collection.json` (a
Postman v2.1 collection) and `env.json` (a Postman environment), so both
can be imported into Postman, and Postman exports can be used here.

Requirements:
- Neovim with the tree-sitter `http` parser (`:TSInstall http`)
- nui.nvim
- curl

Quick start:
1. `:Http create my-api` to create a collection.
2. `<leader>ho` to open the panel, then `a` to add a request.
3. Fill in the request and save it with |:w|.
4. `<leader>hrr` on the request to send it.

2. CONFIGURATION                                         *http-nvim-config*

Each collection is a folder holding `collection.json` (a Postman v2.1
collection) and `env.json` (a Postman environment: a `values` list of
`{ key, value, type, enabled }`). Call `setup()` to choose where those
folders are kept: >lua

    require("http-nvim").setup({
        collection_dir = "~/api",
    })
<
collection_dir      Folder holding one folder per collection. Defaults
                    to `stdpath("data")/http-nvim/collections`. May use
                    `~` and environment variables.
keymaps             Keys per action, see |http-nvim-keymaps|. Each value
                    is a key, a list of keys, or `false` to leave the
                    action unmapped. An action you set replaces its
                    default keys; the others keep theirs. >lua

    require("http-nvim").setup({
        keymaps = {
            open = "<leader>o",
            send = { "<leader>s", "S" },
            undo = false,
        },
    })
<
lsp                 Completion in request edit buffers, from a language
                    server built into the plugin (no install needed).
                    It completes `{{key}}` with the environment
                    variables, the method, header names and common
                    values, and the response handler API inside
                    `> {% %}`. |K| (|vim.lsp.buf.hover()|) on a `{{key}}`
                    shows its value, masked when secret, or that it
                    is disabled or not set. Completion plugins such as blink.cmp or
                    nvim-cmp pick it up as an LSP source; without one,
                    use |i_CTRL-X_CTRL-O|. Defaults to
                    `{ autotrigger = false }`; `false` turns it off.
                    `autotrigger = true` opens Neovim's own completion
                    menu while typing (|vim.lsp.completion.enable()|);
                    leave it off when you use a completion plugin. >lua

    require("http-nvim").setup({
        lsp = { autotrigger = true },
    })
<

==============================================================================
3. COMMANDS                                           *http-nvim-commands*

:Http                                                              *:Http*
                    List the collections in `collection_dir` with
                    |vim.ui.select()| and open the chosen one in the
                    panel. Switching collections closes the panel and
                    the edit buffers of the previous one; if one of
                    them has unsaved changes, nothing is switched.

:Http create {name}                                         *:Http-create*
                    Create the collection {name}: a folder in
                    `collection_dir` with an empty `collection.json` and
                    `env.json`. Files that already exist are left as
                    they are. If no collection is chosen yet, {name}
                    becomes the chosen one.

4. KEYMAPS                                             *http-nvim-keymaps*

Every key can be changed with the `keymaps` option of `setup()`
(|http-nvim-config|). Use the action name from this table as the key.
Panel keys work in the panel, and response keys in the layout that
`send` opens.

  Action            Default key   Description
  `open`              <leader>ho    Open the collection panel (anywhere)
  `preview_last`      <leader>hrp   Show the last response again (anywhere)
  `run_last`          <leader>hre   Send the last request again (anywhere)
  `send`              <leader>hrr   Send the request (panel, edit buffer)
  `help`              g?            Open this help
  `toggle`            <CR> and =    Expand or collapse a folder
  `edit`              e             Edit a request or the variables
  `rename`            r             Rename a request or folder
  `add`               a             Add a request or folder
  `delete`            D             Delete a request or folder
  `cut`               x             Cut, to move with paste
  `copy`              y             Copy, to duplicate with paste
  `paste`             p             Paste the cut or copied item
  `cancel_clipboard`  <Esc>         Cancel a cut or copy
  `move_down`         ]m            Move down among its siblings
  `move_up`           [m            Move up among its siblings
  `undo`              u             Undo the last delete
  `close`             q             Close the response layout
  `focus_headers`     <C-l>         Go to the headers box (response)
  `focus_response`    <C-h>         Go to the response box (headers)

Each key is described below.

<leader>ho          Open the collection panel. If no collection is chosen
                    yet, ask which one first, as |:Http| does.
<leader>hrp         Show the last request and its response again,
                    without sending it.
<leader>hre         Send the last request again, as it is now: from its
                    edit buffer if open (saved or not), else as saved.
<leader>hrr         Send the request under the cursor, or the edit
                    buffer as it is now, and show the response.
                    `{{key}}` is replaced with the environment variable.
g?                  Open this help.
<CR> or =           Expand or collapse the folder under the cursor.
e                   Edit the request under the cursor as a `.http` file
                    (JetBrains HTTP Client format); |:w| saves it.
                    On the environment variables, edit them as
                    `KEY=value` lines; `# KEY=value` is a disabled
                    variable, which `{{key}}` does not use, and
                    `KEY=value # secret` a secret one (Postman type
                    `secret`), whose value the panel masks.
r                   Rename the request or folder under the cursor.
a                   Add a request or folder. `a/b/name` also creates the
                    folders `a/b`; `a/b/` adds only the folders.
D                   Delete the request or folder under the cursor, after
                    confirming.
x                   Cut the request or folder under the cursor, to move
                    it with p.
y                   Copy the request or folder under the cursor, to
                    duplicate it with p.
p                   Paste into the folder under the cursor, or at the top
                    level.
<Esc>               Cancel a cut or copy.
]m                  Move the request or folder down among its siblings.
[m                  Move the request or folder up among its siblings.
u                   Undo the last delete. With 'undofile' set, this
                    works after restarting Neovim.
q                   In the response layout: close it.
<C-l>               In the response layout: go to the headers box.
<C-h>               In the response layout: go back to the response.

5. HIGHLIGHTS                                       *http-nvim-highlights*

The panel buffer (filetype `http-nvim`) defines these groups, styled after
vim-fugitive. Override any of them with |:highlight|.

  httpNvimHeader       Header label, e.g. `Env:`        links to |hl-Label|
  httpNvimHelpHeader   The `Help:` label               links to httpNvimHeader
  httpNvimHelpTag      Key after `Help:`, e.g. `g?`      links to Tag
  httpNvimHeading      Section heading                 links to PreProc
  httpNvimCount        Section count, the `N` in `(N)`   links to Number
  httpNvimEntry        Entry key in `KEY = value`       links to Identifier
  httpNvimEquals       The `=` in an entry              links to Operator
  httpNvimValue        Entry value                     links to String
  httpNvimDisabled     Disabled entry, `# KEY = value`   links to Comment
  httpNvimItemCount    Item count, the `N` in `(N) name` links to httpNvimCount
  httpNvimItem         Item name, e.g. a collection    links to |hl-Directory|
  httpNvimFold         Expand/collapse marker `▸`/`▾`    links to Special
  httpNvimMethod       Request method, e.g. `GET`       links to Keyword
  httpNvimRequest      Request name                    not linked
  httpNvimCut          Item cut with |x|                underlined
  httpNvimCopy         Item copied with |y|             links to httpNvimCut

6. RESPONSE HANDLER                           *http-nvim-response-handler*

A request in the edit buffer can end with a response handler script. After
each response, every variable it sets is added to the environment, or
updated if it exists, and `env.json` is saved: >http

    ### login
    POST {{url}}/login
    Content-Type: application/json

    { "user": "me" }

    > {%
      request.variables.set("token", response.body.data.token)
      client.global.set("auth", "Bearer " + response.body.data.token)
    %}
<
A one-line `> {% ... %}` works too. The script is saved with |:w| as the
request's Postman `test` event, and runs when sending from the panel, the
edit buffer or with `<leader>hre`.

There is no JavaScript engine: only `set("key", value)` calls on
`request.variables`, `client.global`, `pm.environment`, `pm.globals`,
`pm.collectionVariables` and `pm.variables` are read, the rest is ignored.
`secret("key", value)` on the same objects sets the variable as a secret
one (Postman type `secret`, masked in the panel); `set` keeps the type of
an existing variable.
The value is one or more terms joined with `+`:

  `"text"`, `'text'`, `42`              A literal
  `response.body.a[0]["b"]`         The JSON body, through `.key`, `[0]`
                                    and `["key"]`; `.length` of a list
  `pm.response.json().a`            Same as `response.body.a`
  `pm.response.text()`              The body as text
  `response.status`                 The status code, also `pm.response.code`
  `response.headers.valueOf("X")`   A response header, also
                                    `pm.response.headers.get("X")`

A single term that is an object or list is stored as is; anything else is
stored as text. A value that can't be read (e.g. a missing key) is reported
and that variable is left unchanged.
