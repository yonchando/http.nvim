http-nvim helps you do something useful.

==============================================================================
2. CONFIGURATION                                         *http-nvim-config*

Each collection is a folder holding `collection.json` (a Postman v2.1
collection) and `env.json` (its environment variables). Call `setup()` to
choose where those folders are kept: >lua

    require("http-nvim").setup({
        collection_dir = "~/api",
    })
<
collection_dir      Folder holding one folder per collection. Defaults
                    to `stdpath("data")/http-nvim/collections`. May use
                    `~` and environment variables.

==============================================================================
3. COMMANDS                                           *http-nvim-commands*

:Http                                                              *:Http*
                    List the collections in `collection_dir` with
                    |vim.ui.select()| and open the chosen one in the
                    panel. Switching collections closes the panel and
                    the edit buffers of the previous one; if one of
                    them has unsaved changes, nothing is switched.

:Http create {name}                                         *:Http-create*
                    Create the collection {name}: a folder in
                    `collection_dir` with an empty `collection.json` and
                    `env.json`. Files that already exist are left as
                    they are. If no collection is chosen yet, {name}
                    becomes the chosen one.

4. KEYMAPS                                             *http-nvim-keymaps*

<leader>ho          Open your collection RESTApi. If no collection is
                    chosen yet, ask which one first, as |:Http| does.
                    The cursor and scroll position are kept from the
                    last time the panel was closed.
<leader>hrp         Show the last request sent and its response again,
                    from anywhere, without sending it. If the response
                    is still on its way, it fills in when it arrives.
<leader>hre         Send the last request again, from anywhere. Its
                    `{{key}}` values are read from the environment as
                    it is now.
<leader>hrr         With the cursor on a request, send it with curl and
                    show it in a floating layout. The top box shows the
                    method, URL and status code with the time taken.
                    Below it, the left box (70% of the width) shows the
                    response, pretty-printed when it is JSON, or curl's
                    error; the right box (30%) shows the request and
                    response headers from curl's verbose output.
                    Every `{{key}}` in the URL, headers and raw body is
                    replaced with the environment variable `key`;
                    unknown keys are left as is. Disabled headers and
                    non-raw bodies are not sent. Press q in any box to
                    close the layout. All boxes are read-only. <C-l> in
                    the response box moves to the headers box, and
                    <C-h> moves back.
                    Also works in an edit buffer opened with |e|: it
                    sends the buffer as it is now, saved or not.
<CR> or =           Expand or collapse the collection or folder under the
                    cursor.
e                   Edit the request under the cursor in JetBrains HTTP
                    Client format, in a new split above the panel.
                    Closing that window returns to the panel.
                    |:w| saves the request and rewrites the collection
                    JSON file (keys sorted, 4-space indent). Only the
                    first `### name` section is kept; other sections are
                    removed from the buffer. Changing the `### name` line
                    renames the request.
                    On the environment variables, edit them all as
                    `KEY=value` lines, like a `.env` file. Blank lines
                    and `#` comments are skipped, and quotes around a
                    value are removed. |:w| rewrites the environment
                    JSON file; a line without `=` or a repeated name
                    is an error and nothing is saved.
r                   Rename the request or folder under the cursor. Open
                    edit buffers follow the new name.
a                   Add a request or folder: inside the folder under the
                    cursor, next to the request under the cursor, or at
                    the top level on any other line.
                    `get-users` adds a request and opens it for editing.
                    It starts as `GET` with an empty URL; fill in the URL
                    before |:w|.
                    `api/v1/get-users` adds the request inside folders
                    `api/v1`.
                    `api/v1/` (ending with `/`) adds only the folders.
                    Folders that already exist along the path are reused.
D                   Delete the request or folder (with everything in it)
                    under the cursor, after confirming.
                    Edit buffers of the deleted requests are closed;
                    the prompt warns if any has unsaved changes.
x                   Cut the request or folder under the cursor, to move
                    it with |p|. Nothing changes until you paste; the cut
                    item is underlined (`httpNvimCut`).
y                   Copy the request or folder under the cursor, to
                    duplicate it with |p|. The copied item is underlined
                    (`httpNvimCopy`).
p                   Paste into the folder under the cursor, or to the top
                    level on any other line (including a request).
                    After |x| the item is moved and open edit buffers
                    follow the new path. After |y| a copy is added,
                    named `name copy` (`name copy 2`, ...) if the name is
                    taken; the copy stays on the clipboard so |p| can
                    paste it again.
<Esc>               Cancel the cut or copy started with |x| or |y|.
]m                  Move the request or folder under the cursor down
                    among its siblings ([count] places). It never leaves
                    its folder.
[m                  Same as |]m|, but up.
u                   Undo the last deletion, putting the request or folder
                    back where it was and expanding the folders that hold
                    it. Repeat to undo older deletions.
                    When 'undofile' is set, the deletions are kept in a
                    file in the first 'undodir' entry, so |u| still works
                    after restarting Neovim. Otherwise they are lost on
                    exit.
                    |r|, |a|, |p|, |]m|, |[m|, |D| and |u| rewrite the
                    collection JSON file.

5. HIGHLIGHTS                                       *http-nvim-highlights*

The panel buffer (filetype `http-nvim`) defines these groups, styled after
vim-fugitive. Override any of them with |:highlight|.

  httpNvimHeader       Header label, e.g. `Env:`        links to |hl-Label|
  httpNvimHelpHeader   The `Help:` label               links to httpNvimHeader
  httpNvimHelpTag      Key after `Help:`, e.g. `g?`      links to Tag
  httpNvimHeading      Section heading                 links to PreProc
  httpNvimCount        Section count, the `N` in `(N)`   links to Number
  httpNvimEntry        Entry key in `KEY = value`       links to Identifier
  httpNvimEquals       The `=` in an entry              links to Operator
  httpNvimValue        Entry value                     links to String
  httpNvimItemCount    Item count, the `N` in `(N) name` links to httpNvimCount
  httpNvimItem         Item name, e.g. a collection    links to |hl-Directory|
  httpNvimFold         Expand/collapse marker `▸`/`▾`    links to Special
  httpNvimMethod       Request method, e.g. `GET`       links to Keyword
  httpNvimRequest      Request name                    not linked
  httpNvimCut          Item cut with |x|                underlined
  httpNvimCopy         Item copied with |y|             links to httpNvimCut
